§02

Five laws this view adds

The design record's H-1 stands — prose owns the measure, machinery is a footnote you can open — and this proposal keeps its unit (one object per contiguous run). What it changes is what the footnote looks like closed, and how many things on the page get to be a container.

T-1One container, one meaning.The human's prompt is the only filled panel in the document. The reply is bare and the machinery is typography on a rail. When the fill means a person said this, a page of prompts and replies scans in one pass — the same reason Claude, ChatGPT and T3 all converged on it. Left-aligned and full-measure, never a tailed bubble: a document has one margin.
T-2Machinery is a sentence, not a count.verb · object · result. Read a file, Searched a query, Edited a path with its diffstat, Ran a command with its exit. The protocol's closed action union already carries exactly these fields (§04), so the sentence is a projection, never a parse.
T-3Fold by class, not by run.Looking (reads, lists, searches, fetches — and, decided 2026-09-01, shell commands) is high-volume and low-stakes: consecutive looks fold to one line, opened on demand — Ran 3 commands · ls, cat, grep. Acts (edits, delegations, questions) are the session's work product and stay one line each, and a failed command is an act: it breaks the fold and stands alone in red. Past eight lines the whole run closes to one sentence of nouns — 17 commands · 3 edits · 4 reads — never of verbs.
T-4One head per response; anchors live in the margin.The agent's eyebrow appears once per reply, with the agent's name and mark, the observed model and effort as a quiet caption when recorded, and the span and tokens at the right. These are facts about that response, not permanent properties of the worker. Every later segment is still pointable-at: its time sits in the left margin when the column has one, and appears on hover when it does not.
T-5Hue has a grammar: state, content, or address.Red for failed, denied and timed out; green for work still running; everything else about status stays on the ramp. Success is the absence of red. Content may keep its own colour (site icons, diff washes), and §04A lets a teammate keep a small organizational accent because it is how that participant is addressed. Provider branding, prose, glyphs and whole message surfaces stay monochrome.

Three things the construction forces

  1. A concave corner is not a border-radius. The silhouette is a computed clip-path — one function, four corners, one capsule per bay — and each bay's straight run is measured from its laid-out width.
  2. A one-control bay must be a circle, not a zero-length capsule. With zero run the outer fillet has nowhere to sit and the outline doubles back into a spike.
  3. clip-path clips the shadow away with everything else, so while the plate is out, the plate carries the §5 ambient shadow.

export function silhouette(bays: Bay[], inset: number, run: number) {

  return bays.map((b) => capsule(b, inset, r)).join(" ");
}

§04A · revised from ground truth 2026-09-03

Delegation has three geometries

Subagent is a product word, not one storage relation. An ordinary Agent worker is rooted in one invocation but may later receive coordinator follow-ups, peer messages and a resume. An Agent Team teammate is a persistent, addressable participant with optional native colour. A Workflow run is a coordinator-owned fan-out with its own run document, journal and worker set.

Anchor an Agent worker once. Interleave addressable teammates. Group workflow fan-out by run. The renderer follows native ownership instead of making every child look like a team member—or every team member look like one long tool result.

This is chronology as well as styling. Opening an Agent worker reveals one durable child document, including later follow-ups and resumes, without cloning it at each contact. Team boundary messages keep their authored time in the shared transcript. Workflow workers remain grouped under their coordinator run. In every case, copied transport envelopes are provenance, not additional speech.

The minimum durable model

The renderer should not recover these semantics from prose. It needs a three-way relation discriminant; exact parent/call/child ids for Agent workers; team/member/session ids, display name and optional native colour for teammates; and an explicit WorkflowRun → WorkflowAttempt[] → WorkflowPhase[] → WorkflowWorker[] graph. An attempt keeps invocation time, operation, request/tool/task ids, its paired text/structured launch evidence, terminal callback, duration/usage metrics and run id, so a resumed snapshot cannot erase the costly first attempt. The run keeps canonical workflowName evidence, full script and path, args, default model, declared phases, replaceable current progress, exact terminal word, aggregate metrics, untimestamped logs, arbitrary JSON result/error and raw/source cursors. Every Workflow worker keeps stable id/key/index, non-identifying display label, snapshot state, cache/reuse flag, configured model/effort separately from observed response profiles, and provenance for both; normalization must preserve the agent request’s effort instead of asking the renderer to parse Workflow JavaScript. Journal observations and child transcript ids attach as cumulative provenance instead of masquerading as the current snapshot.

Reported is a projection, not a Claude message type. It additionally requires the exact task/tool/result relation and source response; an optional work disclosure requires exact start/end cursors in that member transcript. Without both boundaries, the report body can still fold but the work control is absent. Agent workers always reopen their one canonical child document; workflow worker rows reopen beneath their run, grouped by phase. Search indexes folded bodies, durable workflow results and loaded subthreads. At narrow widths objectives and runtime summaries wrap, low-priority phase descriptions disappear, and colour is never the only identity cue.

Earlier — the head of the document

A session opens on its most recent 200 rows, oldest first, and the older pages sit above. Every chat client loads them when the reader reaches the top; the question is whether reaching the top is enough, or whether the reader has to ask. The shipped app asks with a button. Decided 2026-09-02 (Q7 B): the page above is fetched quietly as the reader nears the top and held; inserting it is still the reader's act. This is the mirror of the live tail's rule — arrival is a notice, not a jump — applied upward:

Nearing the top fetches the page above and holds it. Pushing past the top reveals it. What lands, lands above the viewport, which does not move; a pill says how much arrived; and the head line always states how much is still up there.

The rules

  1. The head line is a marker that counts. At the top of what is loaded: 383 earlier · pull to load, in the marker family's bare-text form. The session's message count is known from the session row, so the number is real; when it is not, the word stands alone. The scrollbar measures the loaded document; this line measures the session.
  2. Nearing the top fetches; it never inserts. Within one viewport of the top the next page is requested and held beside the document. The bar goes indeterminate while the fetch is in flight and stands full once the page is held — weight means readiness, the bar's own rule. Nothing is prepended on approach: the scrollbar stays the loaded document's, and the reader is never surprised by a page they did not ask for.
  3. The pull reveals. At scrollTop 0, wheel or trackpad travel upward accumulates — 120px of it, about two notches or one short flick — and spends the bar. A held page lands the instant the bar is spent. If the pull arrives before the fetch has, the line reads loading 200 earlier over the indeterminate bar and the page lands when it comes; a second pull meanwhile is ignored, not queued. The accumulator decays after half a second of stillness and resets on any downward travel, so drifting to the top never reveals, and a deliberate push always does. Home, PageUp and ↑ at the top reveal on one press. Touch drags the same distance.
  4. Landing never moves the reader. The page is prepended and the row that was under the reader's eye stays exactly where it was. Chromium's scroll anchoring is suppressed at scroll position zero — precisely where this fires — so the prepend measures the first old row before and after and adds the difference to scrollTop itself. The head pill ↑ 200 earlier loaded is the receipt, and it fades; it sits beneath a pinned day pill, never over it, and the head line's count drops by what landed.
  5. The start is a fact, drawn. When there is nothing above, the head line becomes session start · Mon 31 Aug · 23:18:12 and the bar goes. Slack draws “this is the very beginning”; a session's first second is that, said in the room's words. A pull at the start does nothing, and the frame contains its own overscroll so the window never rubber-bands.
  6. Failure is a plain sentence with the next step. The daemon not answering reads the daemon did not answer · retry, muted, with the retry in the line; no red, because nothing was destroyed.
