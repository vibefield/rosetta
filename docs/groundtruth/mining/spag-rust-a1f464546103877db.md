# Claude Code On-Disk Schema Knowledge — Mined from `spaghetti` RFC 012 documents

**Scope note up front:** These four documents are architecture/implementation-plan RFCs for a Rust/TypeScript ingestion engine (`spaghetti`) that *consumes* Claude Code's on-disk data. They are almost entirely about spaghetti's own internal abstractions (fact families, `QualifiedValue`, `EntityKey`, coverage vectors, observer epochs, etc.), **not** a literal schema dump of `~/.claude`. I grepped exhaustively for the literal JSONL field names you listed (`toolUseResult`, `parentUuid`, `leafUuid`, `isSidechain`, `compact_boundary`, `isCompactSummary`, `isApiErrorMessage`, `apiErrorStatus`, `promptSource`, `sessions-index`, `__store.db`, `shell-snapshots`, `paste-cache`, `session-env`, `statsig`) across all four files — **zero hits on any of them**. What follows is everything that *is* genuinely schema-relevant: real native field/file names the RFC authors encountered while building the adapter, verbatim unknown-field/retention-policy quotes, and schema-version evolution notes.

## 1. Native Claude Code on-disk facts actually named in these docs

### 1.1 Directory/session catalog structure
> "Claude catalog identity is the union of top-level transcripts, nested parent-session membership, and session-index entries."
— `archive/012-implementation-plan.md:166-167`

> "Runtime sources include standard children, workflow children, team members, tasks/plans, interactions, modes, and artifact references that require declared scope relationships."
— `archive/012-implementation-plan.md:176-178`

> "the fourth B2 slice (`62a7540`) completes the candidate-only three-adapter identity gate with Claude's index, top-level transcript, and nested-parent membership union plus bounded transcript-head fallback… path-based association identity cannot be retargeted by conflicting `cwd`/project evidence."
— `archive/012-implementation-plan.md:740-746`

> "the independent census now counts Claude UUID-shaped versus opaque nested parents and the nested-only identity delta"
— `archive/012-implementation-plan.md:786-788` (i.e., a session's parent-session reference is sometimes a UUID and sometimes an "opaque"/non-UUID value)

> "Claude also exposed 181 index-only sessions beyond transcript-backed canonical sessions. Omitting them would make discovery incomplete; representing them as fully decoded would be false. Therefore: `discoverable != transcript-backed != hydrated != searchable`"
— `012-evidence-backed-adapters-and-progressive-readiness.md:153-158`

Phase 0 catalog census baseline: **176 projects, 1,414 catalog sessions**, discovered by reading **0.832%** of selected primary-stream bytes (`012-evidence-backed-adapters-and-progressive-readiness.md:148-151`; also `archive/012-implementation-plan.md:170-171`).

Named Claude decoders: `claude-session-record` and `claude-subagent-record` (`archive/012-implementation-plan.md:762-763`); `claude-file-history-blob` decoder bound to a `file-history-blobs` stream (`archive/012-implementation-plan.md:3870`).

Named relation kinds composed for a Claude session (D2 scope composition): root, existing/future **standard children**, **workflow runs/journals and children**, referenced **team/member/inbox objects**, **tasks/plans**, **interactions**, **modes**, and policy-gated **artifact locators** (`archive/012-implementation-plan.md:2969-2971`). A **team-inbox sidecar** file decodes to `Fact::TeamInboxSnapshot` rather than an unknown record (`archive/012-implementation-plan.md:3003-3004`). "Eleven concrete dynamic or related-object relations" were named for the Claude candidate, with "three directory relations" carrying confined relative selectors (`archive/012-implementation-plan.md:3113-3117`); the later-dated `012a` doc says the shipped `scope-programs.json` "declares nine session-rooted relations" (`012a-agent-adaptation-and-engine-boundaries.md:38`) — the count differs between the 2026-08-2x implementation-plan snapshot and the later 012A landing status.

### 1.2 `file-history/` artifact directory (verbatim path template and mechanics)
> "The Candidate declaration now names the exact `file-history/{native-session-id}/{backup-name}` relative locator … Executable conformance renders both sanitized small-corpus file-history objects through the common guard, matches the durable stream selector and home root, and passes the resulting UUID/lowercase-hash/canonical-version paths through Claude's real artifact bootstrap parser."
— `archive/012-implementation-plan.md:3851-3859`

Additional file-history facts:
- Stream/decoder binding: `file-history-blobs` stream → `claude-file-history-blob` decoder, **1 MiB object ceiling** (`archive/012-implementation-plan.md:3870-3873`, `3969`).
- Semantics are `ReplaceDocument`-style (whole-document replace, not append): "content revision or native file-identity replacement remains in one generation, while an observed delete or recreation advances it" (`archive/012-implementation-plan.md:3898-3899`).
- Content-retention policy has three levels: **metadata-only** (retains neither bytes nor hash), **hash-only** (SHA-256 only), **inline** (both bytes and hash) (`archive/012-implementation-plan.md:3883-3884`).

### 1.3 `plans/` sidecars — explicitly *not* the evidence source
> "plans come from `ExitPlanMode`/`EnterPlanMode` tool evidence rather than `plans/<slug>.md` sidecars, which stay snapshot facts with no actor binding"
— `012-evidence-backed-adapters-and-progressive-readiness.md:84-86` (also `012a-agent-adaptation-and-engine-boundaries.md:44-48`)

This confirms Claude Code writes `plans/<slug>.md` files to disk, but spaghetti's "plan" fact family is derived from the `ExitPlanMode`/`EnterPlanMode` tool-call records in the transcript instead, because the sidecar files carry no actor/author binding.

### 1.4 Orphaned `tool_result` handling
> "a `tool_result` whose call fell outside the bounded correlation window keeps its content-block evidence without a guessed tool name"
— `012-evidence-backed-adapters-and-progressive-readiness.md:86-88`; restated at `012a-agent-adaptation-and-engine-boundaries.md:46-48` as "an orphaned `tool_result` claims no tool entity."

### 1.5 Usage/token accounting fields — `message.id` vs `requestId`
> "Non-empty `message.id` is primary, `requestId` is correlation metadata only, exact zero survives, absent buckets remain `Unknown/Missing`, and a malformed usage object emits a bounded diagnostic without dropping the message or replacing the last valid shadow contribution"
— `archive/012-implementation-plan.md:1617-1621`

> "exercised exact repeats, evolving/upward/downward counters, missing buckets, absent and reused `requestId`, actor/session attribution, legacy/v2 numeric divergence, and generation reset"
— `archive/012-implementation-plan.md:1627-1630`

Underlying data-quality census that motivated the usage-v2 migration:
> "The Phase 0B census found 342,861 usage-bearing Claude rows but only 149,077 file-scoped response groups, including 193,784 repeats, 57,150 groups with evolving counters, 111 downward corrections, missing request IDs, and request IDs shared by multiple message IDs."
— `012-evidence-backed-adapters-and-progressive-readiness.md:175-178`

Token-total migration result: **78.52B → 36.88B tokens (2.129×)** old vs. new counting (`012-evidence-backed-adapters-and-progressive-readiness.md:67`), i.e. the legacy row-delta accounting roughly double-counted tokens versus the response-keyed snapshot model.

### 1.6 Settings/session document drift (native field discoveries)
Verbatim (this is the closest thing to a real "unknown/undocumented native field" finding in these docs):
> "The repository-wide native-surface validator also discovered current Claude drift that predates this model slice: `bridge-session` records now include `ownerAccountUuid`/`ownerOrganizationUuid`, an active-session document includes `nameSince`, and `settings.json` includes an `autoMode` policy object. No native values were copied into RFC evidence. A3 classifies the owner UUIDs as sensitive `native-only` bridge correlation metadata, `nameSince` as an opaque `native-only` timestamp-like field, and `autoMode` as sensitive `native-only` configuration rather than effective runtime-mode evidence. The native TypeScript/Rust shapes accept them, but common identities, FTS, logs, telemetry, runtime events, activity, ordering, presence, and effective-mode semantics do not."
— `archive/012-implementation-plan.md:298-310` (repeated near-verbatim at `494-502`)

So: `bridge-session` is a real on-disk record type with `ownerAccountUuid` / `ownerOrganizationUuid` fields; there's a separate "active-session document" with a `nameSince` field; and `settings.json` carries an `autoMode` policy object — all three are accepted by the native parsers but deliberately excluded from every common/derived projection (identity, FTS, logs, telemetry, activity, ordering, effective-mode).

### 1.7 Claude Code version and byte/record size bounds encountered
- Target version referenced throughout: **Claude Code 2.1.223** (`archive/012-implementation-plan.md:126, 509`; `012a-agent-adaptation-and-engine-boundaries.md` describes it as "recognized-unverified").
- Directory-checkpoint bound for Claude: restores at **250,000** entries (candidate bound) vs. a generic 100,000-entry test ceiling (`archive/012-implementation-plan.md:754, 778-780`).
- Record/read framing bounds discovered for Claude records: **64 KiB** logical head record / bounded read-ahead, **4 KiB** checkpoint anchor, **132 KiB** conservative physical read ceiling (`archive/012-implementation-plan.md:751-757`) — explicitly flagged as "fixture evidence rather than ratified policy," not a documented spec limit.
- Schema evolution counters observed: durable schema **v45** (source-record/fact/revision triple storage), **v46** (usage shadow reducer), **v47** (`runtime.actor-run`/`runtime.actor-affiliation` projections), **v48** (normalized coverage storage), **v56** (unknown-record retention) — all internal to spaghetti's SQLite schema, not Claude's own format (`archive/012-implementation-plan.md:249, 1622, 1637, 254, 1556-1557`).
- Claude "decoder contract" version bumps: **17** (usage-v2 response identity introduced) → **18** (unchanged) → **19** (capability-scoped coverage) → **22** (root actor declarations, root usage, child parentage, root team affiliations) (`archive/012-implementation-plan.md:1612-1615, 1997-1998`).
- Rebuild performance: `SCHEMA_VERSION` **64** forces a full rebuild; catalog appears in ~100 ms; full history+search convergence takes **~12 minutes (725 s)** across all eleven fact families on a 3.2 GB Claude corpus, after durable ingest throughput went from 70 → 11,653 records/s (166×) on a frozen 301 MB corpus (`012-evidence-backed-adapters-and-progressive-readiness.md:75-80`).

### 1.8 Codex / Grok on-disk shapes named for contrast (not Claude, but adjacent evidence)
- Codex: bounded first `session_meta` record, `session_meta.payload.cli_version`, `rollout-sessions` declaration, 65,535-byte pre-LF record payload cap, 69,632-byte max physical read (`archive/012-implementation-plan.md:664, 700-717, 899-901`).
- Grok: exactly four admitting sidecars — `chat_history.jsonl`, `events.jsonl`, `signals.json`, `summary.json` — 100,000 entries/depth 8, 1 MiB summary cap (`archive/012-implementation-plan.md:848-857`); usage read from `turn_completed` records in `updates.jsonl`, where an omitted `cacheCreationTokens` leaves that bucket `unknown` rather than being inferred (`012a-agent-adaptation-and-engine-boundaries.md:50-52`).

## 5. Verbatim unparsed/unmodelled/unknown-field quotes and bounded retention policy

Two verbatim items qualify:

**(a) Native-only field classification (quoted in full in §1.6):**
> "…classifies the owner UUIDs as sensitive `native-only` bridge correlation metadata, `nameSince` as opaque `native-only` timestamp-like metadata, and the structured `autoMode` policy as sensitive `native-only` configuration rather than effective runtime mode…" — `archive/012-implementation-plan.md:494-497`

**(b) `RetainedUnknown` bounded-retention policy for genuinely unrecognized native records:**
> "Mapped records carry the exact fact count, transient records become `BufferedIncomplete`, known ignored records carry one closed migration reason code, and `RetainedUnknown` requires exactly one complete `UnknownRecord`. Its family hint is admitted only through a closed machine-code grammar; its always-bounded evidence contains byte count, payload digest, and a value-free shape excerpt, so path-shaped native kinds and payload values cannot enter the common disposition."
— `archive/012-implementation-plan.md:1534-1541`

> "it caps the complete current-generation set, replaces corrections by `SourceRecordId`, suppresses exact replay, computes an ordered digest and exact count/byte totals over every retained occurrence, and selects transport samples by a domain-separated source-identity rank rather than arrival order"
— `archive/012-implementation-plan.md:1544-1547` (continuation of the same unknown-evidence reducer description)

> "Every sample carries only a bounded machine family hint, opaque source/payload digests, and a closed value-free JSON shape whose byte/hash coordinates must match the retained evidence; raw values, native keys, and locators cannot enter it."
— `archive/012-implementation-plan.md:1563-1566`

On the wire this surfaces as `UnknownEvidenceEvent`, "carrying size and digest and never native content" (`012a-agent-adaptation-and-engine-boundaries.md:36`).

## 6. TypeScript vs. Rust disagreement / differential-oracle findings

**No instance of an actual TS/Rust parser disagreement is documented anywhere in these four files.** Every "oracle"/"differential"/"disagree"/"diverge" hit (~150 across the corpus) refers to one of:
- the *legacy-vs-usage-v2* semantic comparator, which explicitly treats a mismatch as expected, not a bug: "The sampler compares both labeled arms under one snapshot, classifies each bucket as equal, legacy-higher, v2-higher, or incomparable, and **never treats expected semantic divergence as oracle failure**." (`archive/012-implementation-plan.md:1879-1882`), with a concrete run showing "all four comparisons were `legacy_higher`, an expected semantic difference rather than an oracle failure" over 153,525 responses / 5,141 actors / 911 usage sessions / 5,289 Ready coverage points, zero foreign-key violations (`archive/012-implementation-plan.md:1886-1896`);
- Codex-specific version *disagreement between configured roots* (not a parser bug, a data-integrity check): "older rollouts are historical evidence rather than a false version contradiction, while disagreement between configured roots fails closed" (`archive/012-implementation-plan.md:902-903`);
- internal invariant checks like "bootstrap/source-state disagreement fails closed" (`archive/012-implementation-plan.md:3505`) and "a scoped wrapper can no longer supply an actor reference that diverges from the validated common revision" (`archive/012-implementation-plan.md:1499-1500`) — these are Rust-internal consistency guards, not cross-language oracle comparisons.

The one governance-relevant "who was right" fact found is a **process failure**, not a parser bug: an audit found the Claude durable bundle had been "marked promoted by a generator that also supplied its own sanitizer approval, while the retained sanitizer input report still had `reviewer: null` and said review was pending" — the bundle was demoted back to `candidate-2026-08-21` (`archive/012-implementation-plan.md:4217-4228`).

### 1.6 Settings/session document drift (native field discoveries)

Verbatim — the closest thing to a real "unknown/undocumented native field" finding in these docs:
